# ASUS ROG STRIX G731GT-H7114 — ALC294 layout 29

I built and tested ALC294 layout 29 on my ASUS ROG STRIX G731GT-H7114.
I added it in this branch without changing existing ALC294 layouts, including 28.

## Hardware and routing

| Item | Value |
| --- | --- |
| Codec | Realtek ALC294, `0x10ec0294` |
| Subsystem | ASUS `0x1043184e` |
| Revision | `0x100004` |
| Address / function group | 0 / 1 |
| Internal speakers | pin `0x14` → DAC `0x02` |
| Headphones | pin `0x21` → DAC `0x03` (connection index 1) |
| Internal microphone | ADC `0x07` → selector `0x24` → pin `0x12` |
| Headset microphone | ADC `0x09` → selector `0x22` → pin `0x19` (`Line In` in macOS) |

I captured a Linux codec dump for local analysis and keep the raw dump private.
I publish only the derived audio resources and hardware routing information.
The stock dump marks only three pins connected: `0x12`, `0x14`, and `0x21`.
Although pin `0x19` is disabled there, I confirmed that my headset microphone
works in Windows 11. I set pin `0x19` to `0x04811020` in this layout and
recorded from the resulting `Line In` input in macOS. I gave the external input
a separate platform path. On my machine, pin `0x19` has no independent jack
presence signal.

I kept the pin defaults from the dump except for my deliberate `0x19` override.
Initialization and wake verbs restore EAPD on `0x14` and `0x21`,
select DAC `0x03` for headphones and pin `0x12` for the microphone selector,
and set the corresponding pin controls. I did not guess vendor coefficients.
I set the initial internal-microphone boost to 1 (10 dB) instead of the dump's
boost 3 (30 dB). I did not copy software EQ or microphone DSP from another laptop.

## Status

- I tested speakers, headphones, the internal microphone and the headset
  microphone on macOS Tahoe with SimpleHDA. I recorded voice through the
  headset microphone, which appears as `Line In`.
- I verified headphone playback after restart, jack unplug/replug and
  sleep/wake without a LaunchAgent. Earlier candidates needed a one-second
  Realtek coefficient toggle; I removed that helper after testing this layout.
- I also tested a full power-off and power-on. Headphones and the `Line In`
  headset microphone still worked. I have not tested other macOS versions or
  hardware revisions.

## Build from source

I built this kext with full Xcode, Git and Python 3 on macOS. To reproduce my
build, clone this fork and these dependencies as sibling directories:

```sh
git clone https://github.com/acidanthera/Lilu.git
git clone https://github.com/acidanthera/MacKernelSDK.git
```

Inside the Lilu checkout:

```sh
ln -s ../MacKernelSDK MacKernelSDK
xcodebuild -project Lilu.xcodeproj -scheme Lilu -configuration Debug \
  -arch x86_64 -derivedDataPath ../build-cache/Lilu CODE_SIGNING_ALLOWED=NO
```

Inside this AppleALC checkout:

```sh
ln -s ../MacKernelSDK MacKernelSDK
cp -R ../build-cache/Lilu/Build/Products/Debug/Lilu.kext ./Lilu.kext
xcodebuild -project AppleALC.xcodeproj -scheme AppleALC -configuration Release \
  -arch x86_64 -derivedDataPath ../build-cache/AppleALC CODE_SIGNING_ALLOWED=NO
```

Use `Debug` instead of `Release` to produce a diagnostic build. The project
build phases generate compressed resources, merge pin configurations and
compile the driver. These are source builds, not modifications to a prebuilt kext.
Build products are under the chosen derived-data directory's `Build/Products`.
I recorded dependency commit hashes and build verification locally in
`../BUILD-RESULTS.json`; the source commits are listed below.

## Manual macOS test

Use a recovery-capable test boot setup. The new AppleALC replaces the existing
AppleALC; do not load two copies. Select **layout 29** using either `alcid=29`
for a temporary test or Data `1d000000` at
`DeviceProperties/Add/PciRoot(0x0)/Pci(0x1F,0x3)/layout-id`.
If an `alcid` argument already exists, replace it rather than appending a second
one. Lilu must load before AppleALC. On Tahoe, retain the existing audio-stack
restoration method; this branch does not install or replace it.

At low volume, check speakers and volume/mute, plug headphones in and check
speaker muting, unplug them and check speaker restoration. Record with both
`Internal Microphone` and `Line In` (the headset microphone). Repeat playback
and recording after sleep/wake and a full power-off. No headphone LaunchAgent
is required for the tested setup. Record the macOS version, Lilu/AppleALC
versions and result of every test, including failures, when proposing upstream
support.

I keep my full machine config, SMBIOS identifiers, credentials and EFI contents
out of this repository. The source here does not mount or modify EFI.
